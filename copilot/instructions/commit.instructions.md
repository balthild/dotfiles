When writing commit messages, if the project has existing commit messages, follow the existing style. Otherwise, use the style described below.

## Commit Style for New Projects

- Use Conventional Commits.
- Use lowercase for the first word after the prefix (e.g., `feat: support something`), unless the first word is a proper noun (e.g., GitHub, OAuth, etc.).
- Keep commit messages as short as possible using concise, high-level summaries of the change.
- Write a single-line message only; do not add a commit body.
